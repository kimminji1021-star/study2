## 핵심 결정 (plan.md §B)

- 보호: Vercel Authentication + "All Deployments"(모든 요금제, 운영 주소 포함). Password Protection은 Hobby 불가, Standard는 운영 주소 미보호. Cron은 운영 배포에서만 → 미리보기 = `main` 운영 배포 + 보호. Preview 배포 안 씀. 첫 빌드는 환경 변수 없이 실패시키고 보호를 켠 뒤 변수 입력(공개 틈 없음). Cron이 보호를 통과하는지는 문서에 없음 → 실제 확인(R1)
- DB: Supabase 공유 풀러 트랜잭션 모드 6543(실패 시 세션 5432). Payload에 `.prepare(` 없음, 잠금은 `set_config(…, true)`·`FOR UPDATE`(트랜잭션 한정)라 호환. SSL은 `DATABASE_CA_CERT`(PEM)로 `ssl: { ca, rejectUnauthorized: true }`, 연결 문자열 `sslmode` 금지(`pg` `connection-parameters.js` 57~60이 문자열 값으로 덮어씀, `pg-connection-string` 2.14.1은 `require`를 `verify-full` 별칭 처리 137~150). 원격인데 인증서 없음 → 풀 설정 함수가 연결 거부(운영 여부 무관, `pg` 기본은 암호화 없음). 풀 `max` = `DATABASE_POOL_MAX`(3~20, 값이 있으면 루프백에도 적용, 없으면 원격 5·루프백 `pg` 기본). 최소 3 — `connectWithReconnect`(db-postgres `connect.js` 4~38)가 연결 1개를 상시 점유해 실사용 `max−1`, 트랜잭션과 트랜잭션 밖 질의가 동시에 필요(R2). 최소 3에서 동시 신청 2건 통합 시험. 예산 5×40=200(무료 풀러 한도), Fluid compute 여부는 M5에서 확인해 다시 계산
- 마이그레이션: M1에서 저장소 플러그인 등록 **뒤** `payload migrate:create initial`(DB 연결 없음) → `src/migrations/`. 빈 임시 DB(`sumbi_migration_check*`)에 적용한 스키마 = 개발 push 스키마(항목별 비교, `media` 플러그인 열 포함). `migrate:check` 스크립트: 실행 전후 `src/migrations/` 목록 비교, S3 없음·가짜 S3 두 설정으로 `migrate:create --skip-empty`, 새 파일이 생기면 지우고 **`index.ts`를 실행 전 내용으로 복원**(Payload `writeMigrationIndex`가 새 파일 기준으로 다시 씀 — `buildCreateMigration.js` 112~114) 뒤 종료 코드 ≠ 0, 복원은 `finally`(`--skip-empty`는 바뀐 점이 있으면 파일을 쓰고 0 — 82~85). 판정: 종료 코드 0 + 실행 뒤 `git status --short src/migrations` 빈 출력. M1에서 `pnpm generate:importmap` 확정(꺼진 플러그인도 `S3ClientUploadHandler`를 import map에 넣음 → `importMap.js` 변경은 예상 결과). 운영 빌드(`VERCEL_ENV=production`)만 점검 → `payload migrate` → `pnpm build`(`vercel.json` `buildCommand`), 운영이 아니면 거부(≠ 0). `prodMigrations` 안 씀. 이후 마이그레이션은 이전 코드와 함께 돌 수 있게(R6). 개발 DB는 push 유지(batch −1이라 migrate 금지), `push`는 루프백일 때만
- 원격 DB 차단: `dev`·`test`·`e2e`·`seed`는 루프백(`localhost`·`127.0.0.1`·`::1`)만. `seed`는 기존 `assertSeedAllowed`(문구 그대로). `tests/integration/setup-env.ts`·`tests/helpers/e2e-env.ts`도 모듈 최상위에서 `.env` 로드 바로 다음 같은 판정(스크립트를 거치지 않은 Vitest·Playwright 실행 차단). 두 파일은 `node:` 내장 모듈과 `src/lib/preflight.ts`만 import(DB 연결 모듈 없음), `setup-env.ts`는 `setupFiles`라 시험 파일보다 먼저 평가
- 저장소: `@payloadcms/storage-s3@3.93.0`(peer `payload: 3.93.0`, 새 직접 의존성 1개, M1에서 설치). **언제나 등록** `s3Storage({ enabled: <다섯 변수 모두 있음>, alwaysInsertFields: true, collections: { media: true }, … })` — 플러그인이 `_objectKey`·`prefix` 열을 더하므로 조건부 등록은 운영 스키마를 마이그레이션과 어긋나게 함(`plugin-cloud-storage` `getFields.js` 153~187, `plugin.js` 12~48). 다섯 변수(`S3_BUCKET`·`S3_ENDPOINT`·`S3_REGION`·`S3_ACCESS_KEY_ID`·`S3_SECRET_ACCESS_KEY`) 일부만 = 오류. `forcePathStyle: true`, 비공개 버킷. `disablePayloadAccessControl`·`signedDownloads`·`clientUploads` 안 씀 → 파일은 `/api/media/file/*`로 `checkFileAccess`(`getFile.js` 21) 뒤 어댑터(30~33). 5MB 코드 한도 유지(Vercel 4.5MB 요청·응답 본문 한도 → 413은 REQ-TOUR-001이 허용), `Media.ts` 안내 문구에 "실제 사이트에서는 4MB 이하"(D7/Q5)
- Supabase Data API: 사용자가 끔(§I.1 8번) — Payload 테이블은 `public`에 RLS 없이 생성되어 켜 두면 공개 키로 신청자 정보 접근 가능. AC-014에서 공개 키 요청 거부 확인
- 정리: `GET /api/cron/cleanup`(라우트 그룹 밖 `src/app/api/cron/cleanup/route.ts` 후보, Payload 404가 아님을 E2E로 확인, 어긋나면 Payload `endpoints`), `force-dynamic`, `Bearer ${CRON_SECRET}` `timingSafeEqual`(길이 달라도 시간 같게), 비밀값 없음·16자 미만 → 항상 401, `GET` 외 405, 200 `{attemptsDeleted, auditLogsDeleted}` + `no-store`. 시도 `attemptedAt < now−10분`, 작업 기록 `occurredAt < now의 UTC 연도−2`(`setUTCFullYear`, 2/29→3/1), 각각 원시 SQL `DELETE` 1회(풀), 중복 실행 0행. 일정 `0 18 * * *`(UTC, 한국 3시대), `regions: ["icn1"]`. Cron이 보호에 막히면(D7/Q6) 미리보기 동안 사용자가 Supabase SQL 편집기에서 수동 정리 SQL(`plan.md` §I.5 — 두 `delete`를 CTE 한 문장으로 묶어 `attempts_deleted`·`audit_logs_deleted` 두 값만 반환, 2월 29일에는 엔드포인트보다 하루 덜 지움) 실행, 자동 삭제 확인은 2단계 출시 조건. README SQL의 표·칸 이름은 정리 구현의 `DELETE`와 같아야 함(AC-015 저장소 규칙). Playwright 시험용 `CRON_SECRET`은 러너 `process.env`에 한 번 만들어 작업자에 물려줌
- 고지: 72시간 계산(실행 간격 최대 24h59m59s → 정상 최대 ~25h10m, 한 번 누락 ~49h10m, 두 번 연속 ~73h10m = 잔여 위험 R4). 새 "수집 항목": `이름, 이메일, 연락처, 신청 인원, 선택한 회차. 부정 신청 방지를 위해 접속 IP를 비밀키로 변환한 값(원래 IP 주소는 저장하지 않음. 10분 동안 신청 횟수를 세는 데만 쓰고, 매일 한 번 자동으로 지워 만든 때부터 늦어도 72시간 안에 삭제)` → 버전 `<확정일>.<새 해시 8자리>`(Q1·Q2 확정). 신청마다 지우는 기존 동작 유지, `rate-limit.ts` 주석만 갱신
- 로그: Payload `logger.options.serializers.err` 가림 — `params`·`detail` 삭제, 문구·스택의 `\nparams:` 뒤 `[REDACTED]`, `cause` 재귀. 메시지 문자열(`msg`)도 `hooks.logMethod`로 같은 가림(Drizzle `parseError.js`·`migrate.js`·`beginTransaction.js`가 `err.message`를 이어 붙임). 이름·`code`·SQL 문 유지. `console.error` 경로와 `payload migrate` CLI 자체 로거는 범위 밖(R18, §B.6)
