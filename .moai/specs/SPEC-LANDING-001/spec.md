## 1. 개요

SPEC-INFRA-001이 만든 임시 홈("숨비투어 · 서비스를 준비 중입니다")을 실제 홈 화면으로 바꾸고, 모든 공개 화면에 공통 머리글·바닥글과 Pretendard 글꼴을 입힌다. 범위는 다음 다섯 가지다.

1. 홈 화면 설정: 운영자가 관리자 화면에서 대표 사진·큰 제목·한 줄 소개를 바꾸는 전역 설정. 대표 사진이 익명 방문자에게 보이도록 미디어 공개 범위를 넓힌다
2. 히어로: 화면 폭을 가득 채우는 사진(없으면 짙은 면), 큰 제목, 소개, 흰 알약 `투어 둘러보기` 버튼. 짙은 면 위 대비 문제를 해결하고 수치를 남긴다
3. 추천 투어: `/tours`와 같은 순서의 공개 투어 최대 6개를 기존 투어 카드로 보이고 `투어 전체 보기` 링크를 둔다
4. 공통 머리글·바닥글·404: 모든 공개 화면의 텍스트 로고·`투어` 링크 머리글, 한 줄 바닥글, 알 수 없는 주소의 404
5. 글꼴·디자인·접근성: Pretendard 직접 호스팅, 2026-11-16 디자인 방향 적용, 랜드마크·본문 바로가기·동작 줄이기

### 2.2 사용자가 확정한 사항 (2026-11-16 인터뷰, 구속력 있음)

- **D1. 홈 화면 구성**: 화면 폭을 가득 채우는 히어로(대표 사진, 큰 제목, 한 줄 소개, 알약 `투어 둘러보기`)와 추천 투어(가장 가까운 예정 회차 순 공개 투어 최대 6개, 기존 투어 카드, 단일 점유 정의, N+1 없음, `투어 전체 보기` 링크). 소개·이용 방법 영역은 없다.
- **D2. 대표 사진**: 운영자가 관리자 화면에서 올리는 전역 설정의 `media` 업로드 필드. 사진이 없으면 깨진 이미지 없이 깔끔한 짙은 히어로. 바꿀 때 코드 변경 없음.
- **D3. 문구**: 큰 제목과 소개도 같은 설정에서 편집, 비어 있으면 한국어 기본 문구.
- **D4. 머리글**: 텍스트 로고 "숨비투어" + "투어" 링크, 모든 공개 화면(홈, `/tours`, 상세, `/apply`, `/apply/complete`, 404). 로그인·언어 전환은 범위 밖.
- **D5. 바닥글**: 모든 공개 화면의 한 줄 바닥글 "© 숨비투어" + "개인정보 처리방침" 자리표시. 죽은 링크나 잘못된 링크가 없도록 동작을 정해 기록한다.
- **D6. 디자인**: 포인트 색 `#00737A` 유지, 2026-11-16 디자인 방향, 짙은 히어로 위 버튼·포커스 대비 해결과 수치 기록, Pretendard를 실제로 불러오기(`next/font/local` 또는 근거 있는 대안, OFL 확인, 대체 글꼴 유지), 접근성(랜드마크, 본문 바로가기, 대표 사진 대체 텍스트, 동작 줄이기).
- **D7. 제외**: 회원, 다국어, 이메일, 배포, 처리방침 본문, 사업자 정보, 관리자 화면의 투어 순서 지정, 애니메이션·WebGL, Claude Design 캔버스 갱신.

Tier는 M으로 정한다. 공개 화면 겉모습이라는 한 도메인이고 프로젝트 원칙을 바꾸지 않는다. 제품 코드는 약 350~500줄, 생성·수정 파일은 약 25개로 Tier M 파일 지침(5~15개)을 넘지만 넘는 부분 대부분이 테스트다. 요구사항 16개·수용 기준 16개로 Tier M 예산 안이며, 넘칠 때의 분할 기준은 `plan.md` §A.3에 둔다. Tier M을 유지하는 이유(plan-audit 1회차 O-1): Tier를 정하는 제품 코드는 약 350~500줄로 Tier M 범위(300~1,000줄) 안이고, 파일 지침을 넘는 몫은 테스트 파일과 글꼴 파일(woff2·라이선스 전문)이다. 분할 기준(`plan.md` §A.3)은 바꾸지 않는다.

### 2.3 이 SPEC이 내리는 결정 (요약 — 근거는 `plan.md` §B)

- **설정은 Payload 전역 설정 하나**: slug `home-settings`, 라벨 `홈 화면 설정`, 필드는 대표 사진·큰 제목·소개 세 개. 읽기는 누구나, 수정은 관리자만. 기본 문구는 코드에서 적용한다(비었거나 공백뿐이면 기본값).
- **대표 사진이 실제로 보이게 미디어 공개 범위를 넓힘**: 업로드 파일 주소는 `media`의 읽기 규칙을 그대로 쓰는데(`plan.md` §A.2 `checkFileAccess`), 지금 규칙은 공개 투어의 대표 이미지만 익명에게 허용한다. 홈 화면 설정이 가리키는 미디어 하나를 허용 목록에 더한다.
- **추천 투어는 기존 조회 계층의 앞 6개**: `listPublishedTours`(익명 읽기, 점유 인원 `GROUP BY` 1회, 단일 계산 지점)의 결과를 그대로 6개로 자른다. 새 정렬·새 점유 계산을 만들지 않는다.
- **짙은 히어로의 대비**: 글자는 흰색, 사진 위에는 균일한 덮개 `rgba(29, 29, 31, 0.65)`, 버튼은 흰 알약에 짙은 글자, 포커스 표시는 흰 외곽선. 히어로 안에서는 포인트 색을 쓰지 않는다.
- **공통 머리글·바닥글은 사용자 화면 레이아웃에서**: `(frontend)/layout.tsx`가 그린다. 관리자 화면은 별도 레이아웃이라 영향이 없다. 알 수 없는 주소는 사용자 화면의 모든 경로 받기 페이지가 `notFound()`를 불러 같은 404를 보인다.
- **글꼴은 공식 파일 그대로 직접 호스팅**: `PretendardVariable.woff2`(v1.3.9)와 OFL 1.1 전문을 `src/app/(frontend)/fonts/`에 두고 `next/font/local`로 불러온다. 외부 CDN 요청 없음, 새 npm 패키지 없음.
- **다른 SPEC 조항의 대체**: SPEC-INFRA-001 REQ-INFRA-005의 "임시 홈(준비 중 문구)" 부분과 SPEC-TOUR-001 REQ-TOUR-014(임시 홈 유지)는 이 SPEC의 REQ-LANDING-004·007이 대체한다. SPEC-INFRA-001 AC-INFRA-008의 홈 부분(`h1` "숨비투어", "준비 중" 문구, 임시 홈의 Tailwind 유틸리티 값 단언 — `tests/e2e/home.spec.ts` 11~32행)은 AC-LANDING-004·013이 대체한다. 같은 AC의 "각 페이지 방문 뒤 E2E 포트 단언"(`expectE2ePort`)은 대체하지 않으며 이 SPEC의 E2E도 따른다. SPEC-TOUR-001 REQ-TOUR-005의 미디어 익명 읽기 범위는 REQ-LANDING-003이 넓힌다. SPEC-TOUR-001 AC-TOUR-013의 "`/`가 사전 렌더링됨" 구조 단언과 AC-TOUR-015(홈의 `/tours` 링크 1개)는 AC-LANDING-015·009가 대체한다.

### 2.4 기록된 가정

- **A1. 관리자 판정**: SPEC-TOUR-001 가정 A1과 같다(`users` 컬렉션 사용자, `src/lib/access.ts` `isAdmin`).
- **A2. 홈 화면 설정은 개인정보가 아니다**: 대표 사진과 홍보 문구는 홈 화면에 그대로 공개되는 내용이다. 그래서 익명 읽기를 허용한다.
- **A3. 운영자는 사진 크기를 스스로 관리한다**: `sharp`가 없어 업로드 원본이 그대로 나간다(`tech.md` §8.1). 관리자 화면 필드 설명으로 가로 2000px·1MB 안팎을 권하고, 이미지 변환·최적화는 이 SPEC 범위 밖이다(`plan.md` §G R6).
- **A4. 배포 시 주소**: 업로드 파일 주소는 `serverURL`을 붙인 절대 주소다(SPEC-TOUR-001 R14). 대표 사진도 같은 규칙을 따르며, 운영 주소 설정은 배포 SPEC이 맡는다.
- **A5. 화면 폭**: 기준 PC 1440px, 콘텐츠 최대 1200px, 모바일 375px, 최소 터치 영역 44×44px(`handoff.md` §3).
- **A6. 글꼴 라이선스**: Pretendard는 SIL Open Font License 1.1(저작권 2021 Kil Hyung-jin, 예약 글꼴 이름 "Pretendard")이다. 원본 파일을 바꾸지 않고 라이선스 전문을 함께 두면 웹 서비스에 번들해 써도 된다(단독 판매 금지, 수정본은 예약 이름 사용 금지). 근거는 `plan.md` §A.2.
- **A7. 대표 사진으로 고른 미디어는 공개된다**: 지금은 관리자 외에 인증된 사용자가 없어 "익명"과 "관리자가 아닌 요청"이 같다. REQ-LANDING-003은 관리자가 아닌 모든 요청을 기준으로 적는다(구현의 `mediaReadAccess`가 관리자가 아닌 요청 전체에 같은 규칙을 쓰기 때문). 관리자가 비공개 투어의 사진(또는 어느 투어도 참조하지 않는 사진)을 대표 사진으로 고르면 그 사진은 문서와 파일 주소 모두 공개된다. 대표 사진은 홈 화면에 공개하려고 고르는 것이므로 의도된 결과로 보고, 관리자 필드 설명에 "고른 사진은 누구나 볼 수 있습니다"를 적는다(`plan.md` §B.1·§G R20).

### 2.5 용어

- **공개 화면**: `(frontend)` 라우트 그룹이 그리는 화면 — `/`, `/tours`, `/tours/[slug]`, `/apply`, `/apply/complete/[ref]`, 사용자 화면 404.
- **사용자 화면 404**: `(frontend)` 경로에서 `notFound()`가 불리거나 사용자 화면이 처리하지 않는 주소가 요청될 때 `(frontend)/not-found.tsx`가 그리는 HTTP 404 페이지.
- **홈 화면 설정**: Payload 전역 설정 `home-settings`. 필드는 대표 사진(`heroImage`), 큰 제목(`headline`), 소개(`intro`).
- **대표 사진**: 홈 화면 설정의 `heroImage`가 가리키는 `media` 문서와 그 업로드 파일. 투어의 대표 이미지(`tours.heroImage`)와 구분한다.
- **히어로**: 홈 화면 맨 위, 화면 폭을 가득 채우는 영역. 대표 사진(또는 짙은 면), 큰 제목, 소개, `투어 둘러보기` 링크를 담는다.
- **짙은 면**: 토큰 `--surface-dark`(`#272729`).
- **덮개**: 사진과 히어로 글자 사이에 까는 반투명 면. 값은 `rgba(29, 29, 31, 0.65)`.
- **덮개 합성**: 덮개 색을 바탕 위에 겹친 색은 채널마다 `α × 덮개 + (1 − α) × 바탕`으로 구하며, 실수값 그대로 쓰고 정수로 반올림하지 않는다. 대비는 이 실수값으로 WCAG 2.x 상대 휘도 공식을 적용해 계산하고, 마지막 대비 값만 소수 둘째 자리에서 반올림한다.
- **최악 배경**: 순백(`#FFFFFF`) 사진 위에 덮개를 위 규칙으로 합성한 색(`rgb(108.1, 108.1, 109.4)`, 반올림하지 않은 값). 사진 위 대비는 이 색으로 잰다.
- **추천 투어**: 투어 목록(`/tours`)과 같은 정렬(SPEC-TOUR-001 REQ-TOUR-009)의 공개 투어 중 앞에서부터 최대 6개.
- **머리글 / 바닥글**: 모든 공개 화면 맨 위의 `banner` 랜드마크 / 맨 아래의 `contentinfo` 랜드마크.
- **본문 바로가기**: 머리글보다 앞에 놓인 첫 포커스 링크. 활성화하면 본문 영역으로 포커스가 옮겨진다.
- **동작 줄이기**: 운영체제·브라우저의 `prefers-reduced-motion: reduce` 설정.
- **전역 설정 원래 값**: 테스트 시작 직전의 `home-settings` 세 필드 값(`heroImage`는 `depth: 0`의 미디어 ID). 바꾸기 전에 gitignore 대상 파일 `.moai/state/verify/landing/home-settings-original.json`에 남기고, 테스트가 끝나면 이 파일의 값으로 되돌린다. 같음 판정은 세 필드를 `값 ?? null`로 맞춘 뒤 비교한다(`plan.md` §B.11).
- **테스트 데이터 표식**: SPEC-TOUR-001·SPEC-APPLY-001과 같다(투어 slug·제목과 미디어 파일 이름 `test-<무작위 값>…`, 신청 이메일 `…@example.test`). 테스트 관리자는 `@example.test` 이메일을 쓴다.

## 3. 요구사항 (GEARS)

패턴 표기: [Ubiquitous] 상시 / [Event-driven] **When** / [State-driven] **While** / [Unwanted] 금지. Tier M 예산(요구사항 16개 이하)에 맞춰 관련 조항을 묶었다.

### 3.1 홈 화면 설정

- **REQ-LANDING-001** [Ubiquitous + Event-driven] Payload 설정에 등록된 전역 설정은 정확히 `home-settings` 하나여야 하며, 그 라벨은 `홈 화면 설정`이어야 한다. 이 전역 설정의 데이터 필드는 대표 사진(`heroImage`, `media`를 가리키는 업로드 필드, 비울 수 있음), 큰 제목(`headline`, 글자, 40자 이하, 비울 수 있음), 소개(`intro`, 글자, 120자 이하, 비울 수 있음) 세 개뿐이어야 하고, 신청자 개인정보를 담는 필드는 없어야 한다. **When** 40자를 넘는 큰 제목이나 120자를 넘는 소개를 저장하려 하면, 시스템은 검증 오류로 거부하고 저장된 값을 바꾸지 않아야 한다.
- **REQ-LANDING-002** [Ubiquitous + State-driven + Unwanted] `home-settings` 읽기는 익명 방문자를 포함한 모두에게 허용되어야 한다. **While** 요청이 관리자의 것이 아니면, 접근 규칙을 적용하는 모든 경로(REST, GraphQL, `overrideAccess: false`인 로컬 API, 관리자 화면)에서 `home-settings` 수정은 거부되고 저장된 값은 바뀌지 않아야 한다. 관리자는 관리자 화면 메뉴의 `홈 화면 설정`에서 세 필드를 편집하고 저장할 수 있어야 하며, 저장한 값은 코드 변경이나 다시 빌드 없이 다음 `/` 요청부터 보여야 한다.
- **REQ-LANDING-003** [State-driven + Unwanted] **While** 요청이 관리자의 것이 아니면(익명 방문자 포함, 가정 A7), `media` 읽기 결과(문서와 업로드 파일 주소)는 공개 투어가 대표 이미지로 참조하는 미디어와 `home-settings`의 대표 사진이 참조하는 미디어만 담아야 한다. 대표 사진을 다른 미디어로 바꾸거나 비운 뒤에는, 이전 미디어는 공개 투어가 참조하지 않는 한 관리자가 아닌 요청의 읽기 결과와 파일 주소에 더는 나타나지 않아야 한다. 이 요구사항은 SPEC-TOUR-001 REQ-TOUR-005의 미디어 익명 읽기 범위만 넓히며, 그 밖의 조항(쓰기 권한, 투어·회차 공개 범위, 사용자 화면이 접근 규칙을 우회하지 않음)은 그대로다.

### 3.2 히어로

- **REQ-LANDING-004** [Event-driven] **When** 방문자가 `/`를 요청하면, 홈 화면은 화면 폭을 가득 채우는 히어로에 큰 제목(`h1`), 소개, `/tours`로 가는 알약 모양 `투어 둘러보기` 링크를 이 순서로 보여야 한다. **When** 큰 제목이 비어 있거나 공백뿐이면 `제주를 가장 가까이, 숨비투어`를, 소개가 비어 있거나 공백뿐이면 `제주의 소규모 투어와 다가오는 회차를 한눈에 확인하세요.`를 보여야 하며, 값이 있으면 앞뒤 공백을 뺀 값을 HTML로 해석하지 않고 글자 그대로 보여야 한다.
- **REQ-LANDING-005** [State-driven + Unwanted] **While** 대표 사진이 설정되어 있고 그 미디어를 익명으로 읽을 수 있으면, 히어로는 그 사진을 영역 전체에 채워 보여야 하며 사진의 대체 텍스트는 그 미디어의 대체 텍스트(`alt`)여야 한다. **While** 대표 사진이 비어 있거나(설정한 적 없음, 관리자가 비움, 미디어 삭제) 익명으로 읽을 수 없으면, 히어로는 짙은 면만 보여야 하며 이미지 요소를 그리거나 이미지 파일을 요청하지 않아야 한다. 어느 경우든 `/`는 HTTP 200으로 응답해야 한다.
- **REQ-LANDING-006** [Ubiquitous + Unwanted] 히어로의 큰 제목과 소개는 흰색(`--on-dark`)이어야 하고, 사진 위에서는 사진과 글자 사이에 균일한 덮개가 있어 최악 배경에서도 글자 대비가 4.5:1 이상이어야 한다. `투어 둘러보기` 링크는 흰 바탕에 짙은 글자(`--color-text`)인 알약이어야 하고, 그 링크의 키보드 포커스 표시는 흰색 2px 이상 외곽선이어야 한다. 히어로 안의 글자·버튼 바탕·테두리·포커스 표시에는 포인트 색(`#00737A`, 짙은 면 위 2.65:1)을 쓰지 않아야 한다. 대비 수치는 `plan.md` §B.5 표에 기록한다.

### 3.3 추천 투어

- **REQ-LANDING-007** [Event-driven + Unwanted] **When** 방문자가 `/`를 요청하면, 홈 화면은 히어로 아래 `추천 투어` 영역에 투어 목록(`/tours`)과 같은 순서의 공개 투어를 앞에서부터 최대 6개 기존 투어 카드로 보여야 하고(카드의 남은 자리는 SPEC-APPLY-001의 점유 인원 정의와 SPEC-TOUR-001의 단일 계산 지점으로 구한 값), 그 아래 `/tours`로 가는 `투어 전체 보기` 링크를 보여야 한다. **When** 공개 투어가 하나도 없으면, 카드 대신 `지금은 공개된 투어가 없습니다.`를 보여야 한다. 공개되지 않은 투어는 어떤 경우에도 보이지 않아야 하며, 홈 화면에는 소개(about) 영역이나 이용 방법 영역이 없어야 한다.
- **REQ-LANDING-008** [Ubiquitous] 홈 화면 데이터(홈 화면 설정과 추천 투어)를 한 번 구할 때 데이터베이스에 보내는 질의 수는 공개 투어 수와 회차 수에 따라 늘지 않아야 하며, 그 질의는 모두 트랜잭션 밖 연결 풀로 나가야 한다. 홈 화면 데이터 조회(홈 화면 데이터 함수가 직접 부르는 `home-settings`·투어 조회)는 익명 접근 규칙(`overrideAccess: false`, 사용자 없음)으로만 실행되어야 한다. `media` 읽기 규칙(`mediaReadAccess`)이 접근 판정 안에서 `req`를 넘겨 부르는 `home-settings` 조회는 이 문장의 대상이 아니며, 그 규칙이 결과를 직접 걸러 내므로 익명 범위를 넓히지 않는다(`plan.md` §B.2). 이 내부 조회도 질의 수 고정 조건에는 포함된다.

### 3.4 공통 머리글·바닥글·404

- **REQ-LANDING-009** [Event-driven + Unwanted] **When** 방문자가 공개 화면을 요청하면, 화면은 맨 위에 같은 머리글을 보여야 한다. 머리글은 `/`로 가는 텍스트 로고 `숨비투어`와 `/tours`로 가는 `투어` 링크 두 개만 링크로 담아야 하며, 로그인·회원가입·언어 전환 컨트롤과 제목 요소(`h1`~`h6`)는 없어야 한다. Payload 관리자 화면(`/admin`)에는 이 머리글이 나타나지 않아야 한다.
- **REQ-LANDING-010** [Event-driven + Unwanted] **When** 방문자가 공개 화면을 요청하면, 화면은 맨 아래 한 줄 바닥글에 `© 숨비투어`와 `개인정보 처리방침(준비 중)`을 보여야 한다. 처리방침 문서가 생기기 전까지 바닥글에는 링크가 없어야 하며, 어떤 공개 화면에도 `href`가 `#`이거나 비어 있거나 없는 링크(`a` 요소)가 없어야 한다. 사업자 정보와 연락처는 바닥글에 넣지 않는다.
- **REQ-LANDING-011** [Event-driven + Unwanted] **When** 방문자가 사용자 화면이 처리하지 않는 주소(예: `/no-such-page`, `/a/b/c`)를 요청하거나 공개 화면이 `notFound()`를 부르면, 응답은 HTTP 404이고 본문은 머리글·바닥글이 있는 사용자 화면 404여야 한다. 이 처리는 `/admin` 아래 관리자 화면과 `/api` 아래 Payload API의 응답을 바꾸지 않아야 한다.

### 3.5 글꼴과 디자인

- **REQ-LANDING-012** [Ubiquitous + Unwanted] 공개 화면은 Pretendard 가변 글꼴을 사이트와 같은 출처에서 내려받아 본문과 제목에 써야 한다. 글꼴 파일은 공식 배포본(v1.3.9 `PretendardVariable.woff2`)을 바꾸지 않은 그대로 저장소에 두고 SIL Open Font License 1.1 전문을 같은 디렉터리에 함께 두어야 하며, `next/font/local`로 불러와야 한다. 공개 화면은 외부 글꼴 서버에 요청을 보내지 않아야 하고, 기존 대체 글꼴 목록(`--font-sans`의 `"Pretendard Variable"`부터 `sans-serif`까지)은 불러온 Pretendard(와 `next/font/local`이 함께 만드는 보정 대체 글꼴) 뒤에 순서 그대로 남아야 한다. Payload 관리자 화면은 이 글꼴을 불러오지 않아야 한다.
- **REQ-LANDING-013** [Ubiquitous + State-driven] 공개 화면은 `handoff.md` §3 "디자인 방향 갱신 (2026-11-16)"을 따라야 한다: 본문 17px(폭 767px 이하 16px)·줄 간격 1.47, 제목 무게 600과 음수 자간, 버튼 역할의 링크는 알약 모양, 카드·버튼에는 그림자 없음(그림자는 사진에만), 섹션은 구분선 대신 면의 바뀜으로 나눈다(홈: 짙은 히어로 → 흰 추천 투어 → 연회색 바닥글). **While** 화면 폭이 375px이면, 홈 화면·`/tours`·투어 상세는 가로 스크롤 없이 모든 내용을 보여야 하고, 머리글의 두 링크와 `투어 둘러보기`·`투어 전체 보기`의 터치 영역은 각각 44×44px 이상이어야 한다.

### 3.6 접근성과 렌더링

- **REQ-LANDING-014** [Ubiquitous + State-driven + Unwanted] 공개 화면마다 `banner`·`main`·`contentinfo` 랜드마크와 `h1`이 각각 정확히 하나 있어야 하고 문서 언어는 `ko`여야 한다. 첫 번째 포커스 가능한 요소는 포커스를 받으면 화면에 보이는 `본문 바로가기` 링크여야 하며, 이를 활성화한 뒤의 다음 Tab은 본문(`main`) 안의 첫 포커스 가능한 요소로 가야 한다. 홈 화면의 추천 투어 영역 제목은 `h2`, 카드 제목은 `h3`이어야 한다. 공개 화면은 스스로 재생되는 애니메이션·동영상·자동 넘김 슬라이드를 갖지 않아야 한다. **While** 방문자가 동작 줄이기를 설정했으면, 공개 화면의 전환 효과 시간은 0.01초 이하여야 한다.
- **REQ-LANDING-015** [Ubiquitous] `/`는 요청 시점에 렌더링되어야 한다(`next/server`의 `connection()` 호출, 빌드의 사전 렌더링 목록에 `/`가 없음). 홈 화면 설정이나 투어 데이터가 바뀌면 다음 요청에 그대로 반영되어야 한다. 기존 공개 화면의 요청 시점 렌더링 규칙(SPEC-TOUR-001 REQ-TOUR-012, SPEC-APPLY-001 신청 화면)은 그대로다.

### 3.7 테스트

- **REQ-LANDING-016** [Ubiquitous] 테스트 실행(`pnpm test`, `pnpm e2e`)은 이 SPEC의 순수 함수(단위: 기본 문구 적용, 추천 투어 자르기, 대비 계산), 전역 설정 등록·검증·접근 규칙, 미디어 익명 읽기 범위, 홈 화면 데이터와 질의 수(통합, 실제 PostgreSQL), 공개 화면의 히어로·추천 투어·머리글·바닥글·404·글꼴·디자인 값·접근성과 관리자 편집 반영(E2E, 테스트 관리자로 로그인)을 검증하고, 홈 화면과 공개 화면의 스크린숏을 1440px·375px 폭에서 남겨야 한다. 테스트는 실제 관리자 계정을 쓰거나 바꾸지 않고, 표식 데이터를 스스로 만들고 지우며, 시작 전 전역 설정 원래 값을 저장했다가 끝나면 그 값으로 되돌려야 한다. `src/lib/` 합산 라인 커버리지 85% 기준과 기존 품질 게이트(타입·빌드·린트·포맷·잠금 파일 불변)는 계속 통과해야 한다.

## 4. 비기능 제약

- **보안**: 홈 화면 설정에는 개인정보가 없다(가정 A2). 문구는 React 기본 이스케이프로 글자로만 그린다(HTML로 해석하지 않음). 미디어 익명 공개는 "공개 투어 대표 이미지 + 홈 대표 사진"으로만 넓히고, 쓰기 권한은 바꾸지 않는다.
- **성능**: 홈 화면 데이터의 질의 수는 고정이다(REQ-LANDING-008). 글꼴 파일(약 2MB)은 미리 받지 않고(`preload: false`) `font-display: swap`으로 글자를 먼저 보인다. 대표 사진은 첫 화면의 가장 큰 요소이므로 `next/image`의 `preload`로 미리 받는다.
- **접근성**: WCAG 2.x 대비(본문 4.5:1, 큰 글자·UI 3:1), 랜드마크, 본문 바로가기, 대체 텍스트, 동작 줄이기, 터치 영역 44×44px.
- **호환**: 새 검증 명령은 Windows PowerShell 5.1에서 동작해야 한다.
- **비용·의존성**: 새 유료 서비스·외부 CDN·새 npm 패키지를 쓰지 않는다. 글꼴은 저장소 파일로 둔다.

수용 기준과 검증 명령은 `acceptance.md`에 둔다.

## 5. 제외 범위 (Out of Scope)

### Out of Scope — 다른 로드맵 기능

- 회원 로그인·회원가입·내 신청 내역 링크(로드맵 4번)
- 언어 전환, 영문 화면, 로케일 경로(로드맵 7번)
- 이메일 알림(로드맵 5번)
- 운영 배포, 업로드 저장소 전환, 운영 `serverURL` 설정(로드맵 8번)

### Out of Scope — 배포 단계의 운영 정보

- 개인정보 처리방침 문서 본문과 그 페이지, 바닥글의 처리방침 링크 연결
- 사업자 정보, 대표 전화번호·문의 이메일·운영 시간 등 연락처(`handoff.md` §4)
- 이용약관, `robots.txt`·사이트맵, 검색 엔진·소셜 공유용 메타 이미지

### Out of Scope — 콘텐츠 관리 확장

- 관리자 화면에서 추천 투어를 고르거나 순서를 정하는 기능(정렬은 `/tours`와 같은 규칙으로 고정)
- 대표 사진 여러 장, 슬라이드, 영역별 문구 편집, 소개(about)·이용 방법 영역
- 업로드 이미지의 크기 변환·형식 변환·자르기(`sharp` 미설치, `tech.md` §8.1)

### Out of Scope — 움직임과 그래픽

- 애니메이션, 시차 스크롤, WebGL, 동영상 히어로, 자동 넘김 슬라이드

### Out of Scope — 디자인 도구와 실험 기능

- Claude Design 캔버스 갱신(`handoff.md` §5)
- Next.js 실험 기능 `global-not-found`(알 수 없는 주소의 404는 사용자 화면 모든 경로 받기 페이지로 처리)
