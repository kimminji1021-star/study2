## 1. 개요

숨비투어의 첫 업무 기능이다. 관리자는 Payload 관리자 화면에서 투어와 회차, 대표 이미지를 등록하고, 방문자는 `/tours`에서 공개된 투어를 둘러본 뒤 `/tours/[slug]`에서 회차와 남은 자리를 확인한다. 범위는 다음 여섯 가지다.

1. 데이터 모델: `Media`(이미지 업로드), `Tours`(투어), `TourSessions`(회차) 컬렉션과 입력 검증
2. 접근 규칙: 쓰기는 관리자만, 익명 읽기는 공개 투어와 그에 딸린 회차·이미지만
3. 남은 자리 계산: 한 곳에서만 계산하며, 지금은 "남은 자리 = 정원"이다. 신청 SPEC(로드맵 3번)이 이 지점을 넓힌다
4. 화면: 투어 목록·상세(한국어), 디자인 토큰과 단순한 공통 조각(상태 배지, 투어 카드, 회차 목록), 임시 홈의 `/tours` 링크
5. 개발용 시드 명령: 핸드오프의 가상 투어와 회차를 넣는다
6. 테스트: 단위·통합·E2E와 저장소 규칙 갱신

이 SPEC이 끝나면 개발자는 `pnpm seed`로 샘플 투어를 넣고, 관리자 화면에서 투어·회차·이미지를 고치고, `/tours`와 `/tours/[slug]`에서 바로 반영된 결과를 볼 수 있어야 한다.

### 2.2 사용자가 확정한 사항 (2026-11-09 인터뷰, 구속력 있음)

- **D1. 화면 수준**: 기능 위주 페이지 + 디자인 토큰. 토큰은 `(frontend)` 범위에서만 적용하고, 상태 배지·투어 카드·회차 목록은 단순한 형태로 만든다. 픽셀 단위로 옮긴 홈·랜딩은 이후 SPEC. 모바일은 375px에서 쓸 수 있는 수준.
- **D2. 이미지**: 지금 업로드 기능을 넣는다. `Media` 컬렉션(대체 텍스트 필수)을 투어 대표 이미지로 쓰고 목록·상세에 보여 준다. 저장은 로컬 디스크(git 추적 제외). 외부 스토리지는 배포 SPEC.
- **D3. 언어**: 한국어만. 경로는 `/tours`, `/tours/[slug]`. 로드맵 7번이 `/ko`, `/en`으로 옮기고 영어 콘텐츠를 더하므로, 그 이전이 추가 작업이 되도록 데이터 모양을 잡는다. Payload localization은 지금 켜지 않는다.
- **D4. 남은 자리**: 당분간 "남은 자리 = 정원". 계산은 한 곳에서만 하고 신청 SPEC이 대기·확정 인원 합계를 빼도록 넓힌다. 마감이거나 시작 시각이 지난 회차는 선택할 수 없다.
- **D5. 홈**: 임시 홈 "숨비투어 · 준비 중"을 유지하고 `/tours` 링크를 더한다. 기존 홈 E2E는 계속 통과한다.
- **D6. 샘플 데이터**: 개발 전용 시드 명령. 운영 환경에서는 거부하고, 다시 실행해도 같은 결과이며, 자동으로 실행되지 않는다.

Tier는 M으로 정한다. 단일 도메인(투어 카탈로그)이고 프로젝트 원칙을 바꾸지 않는다. 예상 파일 수와 코드 줄 수는 Tier M 지침(5~15개, 1,000줄)을 넘을 수 있으나, 늘어나는 부분 대부분이 테스트와 생성 파일(`payload-types.ts`)이다. SPEC-INFRA-001도 같은 이유로 1,372줄에서 Tier M을 유지했다(근거와 추정치는 `plan.md` §A.3).

### 2.3 이 SPEC이 내리는 결정 (요약 — 근거는 `plan.md` §B)

- **sharp 미도입**: 업로드 원본만 저장하고 크기 변환·자르기·초점 기능은 끈다. Payload 3.93은 sharp 없이도 이미지 가로·세로 크기를 읽는다. sharp는 메이저 버전이 0이라 SPEC-INFRA-001의 의존성 규칙(AC-INFRA-005, "메이저 1 이상")과도 충돌한다.
- **투어 설명은 여러 줄 일반 텍스트**: 리치 텍스트(Lexical)는 쓰지 않는다. 운영 데이터는 배포 SPEC 이후에야 생기므로 나중에 바꾸는 비용이 작다.
- **요청 시점 렌더링**: 목록·상세는 사전 렌더링하지 않고 요청마다 데이터를 읽는다. 관리자 수정이 다음 요청에 바로 보인다.
- **남은 자리 계산 지점 하나**: 목록과 상세가 같은 함수를 거친다. 신청 SPEC은 점유 인원 값을 넘겨 주는 부분만 바꾼다.
- **스키마 반영은 계속 개발 모드 자동 반영**: 마이그레이션 파일로의 전환은 배포 SPEC(로드맵 8번)에서 한다(SPEC-INFRA-001 가정 A2 유지).

### 2.4 기록된 가정

- **A1. 관리자 판정**: 관리자는 `users` 컬렉션으로 로그인한 사용자다. 로드맵 4번이 `Members` 인증 컬렉션을 더해도 회원이 관리자 권한을 얻지 않도록, 관리자 판정은 "로그인했다"가 아니라 "`users` 컬렉션 사용자다"로 한다.
- **A2. 지난 회차는 숨김**: 상세 화면은 시작 시각이 지나지 않은 회차만 보여 준다. 방문자가 고를 수 없고, 시간이 지날수록 목록이 끝없이 길어지기 때문이다. 관리자 화면에서는 모든 회차가 보인다.
- **A3. 회차가 있는 투어는 삭제하지 않음**: 투어 삭제 시 회차를 함께 지우면 이후 신청 기록(5년 보관, `product.md` §8.3)까지 연쇄 삭제될 위험이 생긴다. 이번 SPEC부터 회차가 하나라도 연결된 투어의 삭제를 거부한다. 숨기려면 공개 여부를 끈다.
- **A4. 시드는 로컬 DB에만**: 시드는 `NODE_ENV=production`이거나 `DATABASE_URL`의 호스트가 로컬 주소(`localhost`, `127.0.0.1`, IPv6 루프백 `::1`)가 아니면 거부한다. IPv6 루프백은 연결 문자열에 `[::1]`처럼 대괄호로 적히므로 판정은 대괄호를 벗긴 호스트로 한다. 개발용 원격 DB(Supabase 개발 프로젝트)에 시드가 필요해지면 배포 SPEC에서 다시 판단한다.
- **A5. 시드는 이미지를 넣지 않음**: 디자인의 사진도 자리표시 블록이다. 대표 이미지가 없는 투어는 자리표시 블록으로 보여 주고, 실제 사진은 관리자가 올린다.
- **A6. 회차 선택은 화면 상태만**: 상세 화면에서 회차를 고를 수 있지만, 고른 다음의 "신청하기"는 신청 SPEC(로드맵 3번)의 범위다.
- **A7. 투어 목록 경로**: 핸드오프 §1의 확인 필요 항목(별도 목록 페이지 여부)은 사용자 결정 D3에 따라 `/tours`를 별도 목록 페이지로 둔다. `structure.md` 갱신은 sync 단계에서 한다.

### 2.5 용어

- **공개 투어**: 공개 여부(`published`)가 켜진 투어.
- **예정 회차**: 시작 시각이 현재 시각보다 뒤인 회차. 시작 시각이 현재와 같거나 이전이면 **지난 회차**다.
- **남은 자리**: 정원에서 점유 인원을 뺀 값(0 미만이면 0). 이 SPEC에서 점유 인원은 언제나 0이므로 남은 자리는 정원과 같다. 점유 인원은 신청 SPEC이 정의한다(대기·확정 신청의 인원 수 합계, `structure.md` §3).
- **선택 가능한 회차**: 상태가 모집 중이고, 예정 회차이며, 남은 자리가 1 이상인 회차. 이 셋 중 하나라도 아니면 **선택 불가 회차**다.
- **가장 가까운 회차**: 한 투어의 선택 가능한 회차 중 시작 시각이 가장 이른 회차.
- **관리자**: `users` 컬렉션으로 인증된 사용자(가정 A1).
- **익명 방문자**: 인증되지 않은 요청.
- **표시 시간대**: `Asia/Seoul`. 저장은 UTC로 한다.
- **테스트 데이터 표식**: 테스트가 만드는 데이터의 slug·제목·이메일에 붙이는 실행마다 고유한 접두어(예: `e2e-<무작위 값>`). 테스트는 이 표식으로 자기 데이터만 찾고 지운다.

## 3. 요구사항 (GEARS)

패턴 표기: [Ubiquitous] 상시 / [Event-driven] **When** / [State-driven] **While** / [Capability] **Where** / [Unwanted] 금지. Tier M 예산(요구사항 16개 이하)에 맞춰 관련 조항을 묶었다.

### 3.1 데이터 모델

- **REQ-TOUR-001** [Ubiquitous + Event-driven] Payload 설정은 이미지 업로드 컬렉션 `media`를 등록해야 한다. 이 컬렉션은 JPEG·PNG·WebP 이미지만 받고, 대체 텍스트를 필수로 하며, 파일을 git 추적에서 제외된 로컬 디렉터리에 원본 그대로 저장해야 한다. 업로드 컬렉션은 크기 변환·자르기·초점 기능을 제공하지 않아야 한다. **When** 대체 텍스트가 비어 있거나, 허용하지 않은 형식(SVG 포함)의 파일이나 5MB(5 × 1024 × 1024바이트)를 넘는 파일이 제출되면, 업로드는 문서를 만들지 않고 파일을 저장하지 않은 채 검증 오류로 끝나야 한다. 5MB 초과 거부는 `media` 컬렉션 자체가 판정해 로컬 API와 REST 어느 경로로 제출되든 적용되어야 한다. 다만 REST 요청은 그보다 앞선 요청 본문 처리 단계의 크기 한도에 먼저 걸려 HTTP 413으로 끝날 수 있으며, 이 경우에도 문서와 파일은 생기지 않아야 한다. 정확히 5MB인 파일은 크기 때문에 거부되지 않아야 한다.
- **REQ-TOUR-002** [Ubiquitous + Event-driven] Payload 설정은 투어 컬렉션 `tours`를 등록해야 한다. 투어는 제목, slug, 요약, 설명(여러 줄 일반 텍스트), 대표 이미지(선택, `media` 참조), 소요 시간(분 단위 정수, 1 이상), 집결 장소, 가격 안내 문구, 공개 여부(기본값: 꺼짐)를 가져야 하며, 대표 이미지를 뺀 나머지는 필수다. slug는 영문 소문자·숫자와 단어 사이 하이픈 하나로만 이루어져야 하고 모든 투어에서 고유해야 한다. **When** 형식에 맞지 않거나 이미 쓰인 slug, 1 미만이거나 정수가 아닌 소요 시간, 비어 있는 필수 값이 제출되면, 저장은 검증 오류로 끝나고 문서를 만들거나 바꾸지 않아야 한다.
- **REQ-TOUR-003** [Ubiquitous + Event-driven] Payload 설정은 회차 컬렉션 `tour-sessions`를 등록해야 한다. 회차는 소속 투어(필수), 시작 일시와 종료 일시(필수), 정원(정수, 1 이상), 상태(모집 중 / 마감, 기본값: 모집 중)를 가져야 한다. 일시는 UTC로 저장되어야 하고, 관리자 화면의 일시 입력은 `Asia/Seoul` 기준으로 해석되어야 한다. **When** 종료 일시가 시작 일시와 같거나 앞서는 값, 1 미만이거나 정수가 아닌 정원이 제출되면, 저장은 검증 오류로 끝나고 문서를 만들거나 바꾸지 않아야 한다.
- **REQ-TOUR-004** [Ubiquitous] Payload 설정에 등록된 컬렉션 중 Payload 시스템 컬렉션(slug가 `payload-`로 시작)을 뺀 목록은 정확히 `users`, `media`, `tours`, `tour-sessions`여야 한다.

### 3.2 접근 규칙과 데이터 무결성

- **REQ-TOUR-005** [Unwanted + State-driven] `media`, `tours`, `tour-sessions`의 생성·수정·삭제는 관리자만 할 수 있어야 하며, 익명 방문자의 생성·수정·삭제 요청은 데이터를 바꾸지 않고 거부되어야 한다. **While** 요청이 인증되지 않은 상태이면, 읽기 결과는 공개 투어, 공개 투어에 속한 회차, 공개 투어가 대표 이미지로 참조하는 미디어(문서와 파일)만 담아야 한다. 이 규칙은 사용자 화면, REST API, GraphQL API, 업로드 파일 주소에 똑같이 적용되어야 하며, 사용자 화면의 데이터 조회도 접근 규칙을 우회하지 않아야 한다.
- **REQ-TOUR-006** [Event-driven + Unwanted] **When** 회차가 하나 이상 연결된 투어의 삭제가 요청되면, 시스템은 투어와 회차를 삭제하지 않고, 연결된 회차를 먼저 정리해야 한다는 안내를 담은 오류로 끝나야 한다. 오류 메시지는 `acceptance.md` AC-TOUR-007이 정한 영문 고정 문구를 포함해야 한다(`language.yaml`의 `error_messages: en`).

### 3.3 남은 자리와 표시 규칙

- **REQ-TOUR-007** [Ubiquitous] 회차의 남은 자리와 선택 가능 여부는 하나의 계산 지점에서만 결정되어야 하며, 투어 목록과 투어 상세는 모두 이 지점의 결과를 써야 한다. 남은 자리는 정원에서 점유 인원을 뺀 값(0 미만이면 0)이고, 이 SPEC에서 점유 인원은 0이다. 회차는 상태가 모집 중이고, 시작 시각이 현재 시각보다 뒤이며, 남은 자리가 1 이상일 때만 선택 가능하다.
- **REQ-TOUR-008** [Ubiquitous] 사용자 화면의 모든 일시는 서버의 시간대 설정과 관계없이 `Asia/Seoul` 기준의 한국어 표기(월·일·요일·오전/오후 시각)로 보여야 하고, 소요 시간은 분 단위 값을 시간·분 표기(예: 4시간 30분)로 보여야 한다.

### 3.4 화면

- **REQ-TOUR-009** [Event-driven] **When** 방문자가 `/tours`를 요청하면, 프론트엔드는 공개 투어만 카드로 보여야 한다. 각 카드는 대표 이미지(없으면 자리표시 블록), 제목, 요약, 소요 시간, 가격 안내 문구, 상태 배지, 투어 상세로 가는 링크를 담아야 한다. 선택 가능한 회차가 있는 투어의 카드는 "모집 중" 배지와 가장 가까운 회차의 일시, "남은 자리 N / 정원 M"을 보여야 하고, 없는 투어의 카드는 "모집 마감" 배지를 보여야 한다. 카드는 선택 가능한 회차가 있는 투어를 먼저, 가장 가까운 회차의 시작 시각이 이른 순으로 놓고, 그다음 나머지 투어를 제목 순으로 놓아야 한다.
- **REQ-TOUR-010** [Event-driven] **When** 방문자가 공개 투어의 `/tours/[slug]`를 요청하면, 프론트엔드는 제목, 대표 이미지(없으면 자리표시 블록), 설명, 소요 시간, 집결 장소, 가격 안내 문구와 예정 회차 목록을 보여야 한다. 회차 목록은 시작 시각 순이며 지난 회차를 담지 않아야 한다. 각 회차는 일시, "남은 자리 N / 정원 M", 상태 배지를 보여야 하고, 선택 가능한 회차는 하나만 고를 수 있는 선택 항목으로, 선택 불가 회차는 고를 수 없는 상태로 보여야 한다. 예정 회차가 없으면 예정된 회차가 없다는 안내를 보여야 한다.
- **REQ-TOUR-011** [Event-driven] **When** 방문자가 존재하지 않는 slug나 공개되지 않은 투어의 slug로 `/tours/[slug]`를 요청하면, 프론트엔드는 HTTP 404로 응답하고 그 투어의 내용을 보여 주지 않아야 한다.
- **REQ-TOUR-012** [Ubiquitous + Event-driven] `/tours`와 `/tours/[slug]`는 운영 빌드에서 사전 렌더링되지 않고 요청마다 데이터를 읽어야 한다. **When** 관리자가 투어·회차·이미지를 바꾼 뒤 방문자가 해당 페이지를 다시 요청하면, 프론트엔드는 다시 빌드하지 않아도 바뀐 내용을 보여야 한다.
- **REQ-TOUR-013** [Ubiquitous + State-driven] 디자인 토큰(`tokens.css`의 색·글자·간격 등)은 `(frontend)` 라우트 그룹에서만 로드되어야 하며, Payload 관리자 화면은 이 토큰을 로드하지 않아야 한다. 상태 배지는 색만으로 상태를 구분하지 않고 아이콘과 글자를 함께 보여야 한다. **While** 화면 폭이 375px이면, `/tours`와 `/tours/[slug]`는 가로 스크롤 없이 모든 내용을 보여야 하고 회차 선택 항목의 터치 영역은 44×44px 이상이어야 한다.
- **REQ-TOUR-014** [Event-driven] **When** 방문자가 `/`를 요청하면, 프론트엔드는 기존 임시 홈("숨비투어" 제목과 "준비 중" 문구)을 유지한 채 `/tours`로 가는 링크를 보여야 한다.

### 3.5 시드와 테스트

- **REQ-TOUR-015** [Ubiquitous + Event-driven + Unwanted] 프로젝트는 개발 전용 시드 명령(`pnpm seed`)을 제공해야 하며, 이 명령은 핸드오프의 가상 투어 3개(한라산 영실·우도 자전거·해녀 체험)를 공개 상태로, 각각 예정 회차와 함께 넣어야 한다. 시드는 빌드·개발 서버·테스트 실행 중에 자동으로 실행되지 않아야 한다. **When** 같은 slug의 투어가 이미 있으면, 시드는 그 투어와 회차를 바꾸지 않고 건너뛰어야 하며, 따라서 여러 번 실행해도 투어 수가 늘지 않아야 한다. **When** `NODE_ENV`가 `production`이거나 `DATABASE_URL`의 호스트가 로컬 주소가 아니면, 시드는 데이터베이스에 쓰기 전에 거부 이유를 출력하고 0이 아닌 종료 코드로 끝나야 한다.
- **REQ-TOUR-016** [Ubiquitous] 테스트 실행(`pnpm test`, `pnpm e2e`)은 이 SPEC의 계산·표시 도우미(단위), 컬렉션 검증·접근 규칙·조회 계층·시드(통합), 목록·상세·404·홈 링크(E2E)를 검증해야 한다. 테스트는 필요한 데이터를 테스트 데이터 표식을 붙여 스스로 만들고 끝나면 지워야 하며, 시드 데이터나 개발자가 만든 데이터에 기대지 않아야 한다. `src/lib/` 합산 라인 커버리지 85% 기준과 SPEC-INFRA-001의 품질 게이트(타입·빌드·린트·포맷)는 계속 통과해야 한다.

## 4. 비기능 제약

- **보안**: 공개 범위는 REQ-TOUR-005가 정한다. 업로드는 SVG를 받지 않는다(스크립트 삽입 위험). 이 SPEC은 개인정보를 다루지 않는다. 비밀 값 비노출 원칙(REQ-INFRA-010)은 그대로 적용한다.
- **접근성**: 상태는 색·아이콘·글자로 함께 표시하고, 회차 선택은 키보드로 조작할 수 있는 기본 선택 요소를 쓴다. 문서 언어는 `ko`. 대표 이미지는 `media`의 대체 텍스트를 쓴다.
- **다국어 대비**: 제목·요약·설명·집결 장소·가격 안내 문구·대체 텍스트는 로드맵 7번에서 필드 단위 다국어로 바뀔 수 있는 독립 텍스트 필드로 둔다. slug는 언어와 무관한 값이고, 소요 시간은 숫자로 저장해 표기만 언어별로 바꾼다. 데이터 조회와 표시 계산은 경로 파일 밖(`src/lib/`)에 두어 경로를 `[locale]` 아래로 옮기는 일이 파일 이동으로 끝나게 한다.
- **Windows 호환**: 새 스크립트도 POSIX 셸 전용 구문 없이 동작해야 한다(REQ-INFRA-002).
- **비용**: 새 유료 서비스나 외부 스토리지를 쓰지 않는다. 새 npm 패키지를 추가하지 않는다.

수용 기준과 검증 명령은 `acceptance.md`에 둔다.
